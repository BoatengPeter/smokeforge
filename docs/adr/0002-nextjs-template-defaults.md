# 0002 — Next.js template defaults and agent skills

- Status: Accepted
- Date: 2026-11-12

## Context

The first M3 registry slice is a Next.js template. It must support a standalone
frontend and backend-enabled Next apps using `route.ts` Route Handlers.

## Decision

- One composable `next` base; standalone means no backend overlays.
- Next.js 16.4.6, React 19.3.0, TypeScript 5.9.3, Node 24 LTS.
- Package managers: pnpm default; npm and bun selectable through
  `package_manager`.
- App Router with `src/`, Tailwind 4, Jest, Playwright, React Hook Form + Zod,
  and Zustand with per-request stores.
- Metadata API, OpenGraph image, sitemap, and robots are base defaults.
- Backend API uses `src/app/api/**/route.ts`; no server-actions-as-API default.
- Optional overlays: Postgres/Drizzle, Better Auth (session) + TOTP, PostHog,
  Docker, and CI.
- PostHog is client-only, privacy-first, and consent-gated.
- Project-scoped frontend skills ship inside the template under
  `.agents/skills` and `.claude/skills`, with `AGENTS.md`, `CLAUDE.md`, and
  `skills-lock.json`.

## Consequences

- Base app files must build with pnpm, npm, and bun.
- Lockfiles are generated by the first install; exact package pins ship in
  `package.json`.
- Next-specific skills stay in the generated app, not the CLI repo.
- Backend/mobile/desktop defaults remain separate decisions.
